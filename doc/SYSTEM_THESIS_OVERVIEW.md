# SwiftChat 系统说明文档

## 1. 文档用途

本文档基于当前桌面客户端工程与后端工程整理而成，用于后续毕业论文撰写、功能用例设计、系统架构图绘制、角色权限分析、模块划分说明以及部署结构说明。

本文档关注的是完整系统，而不是单一前端仓库，因此会同时描述客户端、服务端、实时通信链路、数据存储与后台管理能力。

## 2. 项目概述

### 2.1 项目名称

- 系统名称：`SwiftChat` / `chat-service` 配套桌面即时通信系统
- 客户端形态：桌面端聊天客户端
- 系统架构形态：`C/S`（Client/Server）架构

### 2.2 项目定位

本系统是一个面向桌面端场景的即时通信平台，围绕“账号认证、联系人关系、单聊群聊、文件传输、消息推送、后台管理、版本控制”展开建设。系统前端采用 Electron 封装桌面客户端，后端采用 Spring Boot 构建业务服务，并通过 HTTP 接口与 WebSocket 双通道实现业务交互与实时消息通信。

从业务定位上看，该系统既覆盖普通用户的聊天业务，也覆盖管理员对平台运行状态、用户数据、群聊数据、版本信息和系统参数的后台管理能力，因此属于一个同时具备“用户端业务系统”和“管理端支撑系统”的综合型即时通信平台。

### 2.3 建设目标

- 提供完整的桌面端即时通信能力
- 实现用户注册、登录、资料维护与权限识别
- 支持好友体系、群聊体系与申请审核流程
- 支持文本、图片、文件、视频等消息形态传输
- 支持在线消息实时推送与离线消息补发
- 支持管理员对平台进行配置管理与数据管理
- 支持版本发布管理与客户端升级检查

## 3. 系统总体组成

从整体上看，本系统由五个核心部分组成：

1. 桌面客户端
2. 业务服务端
3. WebSocket 实时通信服务
4. 数据存储与缓存组件
5. 后台管理模块

### 3.1 桌面客户端

桌面客户端是用户直接接触的交互层，负责登录注册、联系人管理、聊天会话、群聊操作、设置管理、文件处理、窗口控制、视频通话界面与后台管理入口展示。当前仓库即为该客户端工程。

### 3.2 业务服务端

业务服务端负责提供账号、联系人、群组、申请、消息、版本、后台管理等 REST API，并承担核心业务规则校验、数据持久化、权限控制与结果封装。

### 3.3 WebSocket 实时服务

实时服务负责建立在线连接、校验用户身份、维护用户连接关系、转发实时消息和视频通话信令，保证系统具备即时通信的实时性。

### 3.4 数据存储与缓存组件

- MySQL：保存用户、群聊、申请、消息、版本等核心业务数据
- Redis：保存 token、缓存、心跳、在线状态、消息辅助数据与离线消息相关信息
- SQLite：客户端本地保存会话、消息等本地数据，增强桌面端使用体验

### 3.5 后台管理模块

后台管理模块主要面向管理员，提供用户管理、群聊管理、系统设置、自定义账号管理和版本管理能力，用于保障平台的可运营性与可维护性。

## 5. 系统用户角色与权限设计

## 5.1 角色划分

本系统主要包含两类核心业务角色和两类系统参与者。

### 5.1.1 普通用户

普通用户是系统的主要使用者，具备聊天业务相关的前台权限，包括注册登录、个人资料维护、好友添加、联系人管理、群聊参与、消息发送、文件传输、申请审核等。

### 5.1.2 管理员

管理员在具备普通用户基础能力的前提下，还拥有后台管理权限，可进入后台管理界面，对用户、群聊、系统参数、自定义账号、版本信息进行维护。

### 5.1.3 桌面客户端

桌面客户端作为系统交互载体，本身不是业务角色，但在系统设计中属于重要参与者。它承担 HTTP 请求发起、WebSocket 连接维护、消息展示、本地缓存、本地文件处理与窗口管理等职责。

### 5.1.4 外部基础设施

MySQL、Redis 等基础设施不直接参与业务操作，但在系统运行中承担数据持久化、缓存、会话控制、消息辅助存储等支撑职责。

## 5.2 权限边界

### 5.2.1 公开接口权限

无需登录即可访问的接口主要集中在账号初始化阶段：

- 获取验证码
- 注册
- 登录

### 5.2.2 登录后权限

登录后用户可访问：

- 个人信息维护
- 联系人管理
- 好友申请处理
- 群聊创建与管理
- 聊天消息与文件处理
- 系统基础设置与本地设置

### 5.2.3 管理权限

管理员可额外访问：

- 后台用户管理
- 后台群聊管理
- 后台系统设置
- 自定义账号管理
- 版本管理

## 7. 前端工程结构说明

根据当前仓库结构，客户端主要分为三层。

### 7.1 主进程层 `src/main`

主进程层负责：

- Electron 主窗口创建
- 托盘创建与菜单管理
- 后台管理窗口打开
- IPC 事件注册
- 本地文件服务与文件处理
- 本地数据库与桌面资源能力调用

### 7.2 预加载层 `src/preload`

预加载层用于衔接渲染进程与 Electron 能力，把 IPC 与部分桌面 API 安全地暴露给前端界面调用。

### 7.3 渲染进程层 `src/renderer/src`

渲染进程层承担用户交互界面与业务逻辑展示职责，主要包括：

- `views`：业务页面
- `components`：可复用组件
- `api`：接口封装
- `stores`：Pinia 状态管理
- `router`：前端路由定义
- `utils`：工具函数与请求封装

## 8. 后端分层结构说明

根据后端资料，服务端采用典型分层设计：

- 接入层：Controller + Netty WebSocket 接入
- 业务层：Service / ServiceImpl
- 数据访问层：Mapper + XML
- 数据层：MySQL + Redis

### 8.1 接入层

接入层负责接收客户端请求、解析参数、校验 token、转交业务层处理，并统一对外返回结果。

### 8.2 业务层

业务层负责：

- 账号认证逻辑
- 联系人与群聊逻辑
- 消息存储与消息推送逻辑
- 申请审核逻辑
- 后台管理逻辑

### 8.3 数据访问层

数据访问层通过 MyBatis-Plus 与 Mapper XML 完成数据库交互，实现对用户、群聊、消息、申请、版本等数据实体的增删改查。

### 8.4 缓存与辅助层

Redis 用于承担：

- token 存储
- 心跳状态管理
- 在线状态辅助记录
- 离线消息辅助处理
- 系统设置与缓存数据保存

## 9. 关键业务流程说明

## 9.1 用户登录流程

1. 用户打开客户端进入登录页面
2. 客户端请求验证码接口
3. 用户输入账号、密码、验证码发起登录
4. 服务端验证账号信息并生成 token
5. 客户端保存 token 与用户信息
6. 客户端进入主页面并初始化联系人、会话与系统设置数据
7. 客户端建立 WebSocket 连接，进入在线状态

## 9.2 单聊消息发送流程

1. 用户在聊天窗口输入消息或选择文件
2. 客户端调用 `/api/chat/send` 或上传接口
3. 服务端写入消息数据
4. 服务端通过 Redis Topic 或 WebSocket 转发消息
5. 目标用户在线时实时接收消息
6. 目标用户不在线时写入离线消息辅助结构
7. 用户下次上线后由系统补发消息或同步会话状态

## 9.3 好友申请流程

1. 用户搜索目标账号
2. 客户端发起好友申请
3. 服务端保存申请记录
4. 目标用户在申请列表中查看申请
5. 目标用户通过或拒绝申请
6. 若通过，则建立联系人关系并刷新双方联系人列表

## 9.4 群聊创建与邀请流程

1. 用户发起新建群聊操作
2. 填写群信息并邀请初始成员
3. 服务端创建群数据并建立群成员关系
4. 客户端更新群联系人列表
5. 后续可继续邀请成员、修改群资料、查看群详情或解散群聊

## 9.5 管理员后台操作流程

1. 管理员登录客户端
2. 主进程根据管理员身份开放后台入口
3. 管理员打开后台管理窗口
4. 在后台页面进行用户、群聊、系统参数、版本等操作
5. 系统将管理结果持久化并反馈到客户端页面

## 10. 系统架构说明

## 10.1 总体架构

本系统总体采用“桌面客户端 + 业务服务端 + WebSocket 实时服务 + 数据层 + 管理后台”的复合架构。

可抽象为以下五层：

1. 表现层：桌面客户端界面与后台管理界面
2. 通信层：HTTP API 与 WebSocket
3. 业务层：账号、聊天、联系人、群聊、管理等业务服务
4. 数据访问层：Mapper 与数据库访问组件
5. 数据支撑层：MySQL、Redis、本地 SQLite

## 10.2 前后端通信方式

### HTTP 通道

用于处理：

- 登录注册
- 列表查询
- 表单提交
- 数据保存
- 文件上传下载
- 后台管理操作

### WebSocket 通道

用于处理：

- 在线连接建立
- 实时消息推送
- 状态同步
- 视频通话信令交互

### IPC 通道

客户端内部还存在 Electron 主进程与渲染进程之间的 IPC 通信，用于完成：

- 打开新窗口
- 窗口控制
- 获取头像缓存
- 打开目录
- 文件移动与保存
- 本地数据库目录查询
- 获取版本信息

- `ChatSessionUser`：用户会话关联对象
- `ChatMessage`：聊天消息对象
- `AppVersion`：应用版本信息
- `CustomAccount`：后台自定义账号信息

## 12. 安全设计说明

## 12.1 身份认证

系统通过 token 机制维持登录状态：

- HTTP 请求通过 Header `authorization` 传递 token
- WebSocket 连接通过 Query 参数传递 token

## 12.2 权限控制

系统对接口进行分级控制：

- 公开接口
- 登录后接口
- 管理员接口

其中管理员接口主要集中在 `/api/admin/**` 与 `/api/version/**` 下。

## 12.3 在线状态控制

系统通过 Redis 心跳与 Netty 连接管理机制判断在线状态，并在异常断开时执行连接清理和状态更新。

## 12.4 会话安全

系统支持同用户 token 替换校验，用于避免旧 token 与新 token 并发带来的状态混乱问题。

## 13.5 可运营性

管理员后台、系统设置、自定义账号和版本管理能力，使系统具备较好的平台化运营基础。

## 17. 总结

SwiftChat 是一个基于 Electron 桌面客户端与 Spring Boot 后端服务构建的即时通信系统。系统不仅具备基础的注册登录、单聊群聊、文件收发、联系人管理、申请审核等通信能力，还引入了 WebSocket 实时通信、管理员后台管理、版本管理、系统参数设置以及本地桌面增强能力，使其具备较完整的信息系统形态。

从论文研究与系统设计角度来看，该系统具备较好的分析价值：一方面，它涵盖了前端桌面化、后端业务化、实时通信化、多角色权限化等多个技术维度；另一方面，它在功能上已经形成较完整的业务闭环，能够支撑后续毕业论文对需求分析、系统设计、功能实现、架构建模与图表绘制的系统化展开。
